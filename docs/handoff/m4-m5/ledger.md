# M4 & M5 Execution Ledger (v1.0 Release)

This ledger records every engineering ruling made while upgrading RouterOS/xray-core support, completing the remaining backend API/CLI features, building the embedded Svelte 5 Web UI (M4), and polishing the v1.0 open-source release (M5).

## Target Environment Upgrades

- **RouterOS support upgraded** from hardcoded `7.25` / `7.23.8` to release-line verified branches:
  - `7.25.1` stable (and `7.25.x` point patches where `patch >= 1`, plus `7.25` base)
  - `7.24.6` long-term (and `7.24.x` point patches where `patch >= 6`)
  - `7.23.8` legacy long-term (and `7.23.x` point patches where `patch >= 8`)
- **xray-core tested range** extended to `v26.11.9`.

## Rulings

- `Ruling: Use release-line version matching in adapters.DetectProfile and POSIX ERE guards in BuildInstaller (e.g. ^7\.25(\.[1-9][0-9]*)?$) — MikroTik ships frequent point CVE patches on the stable (7.25.x) and long-term (7.24.x) tracks without changing container or firewall syntax, while rejecting non-canonical .0 patches, older unverified patches, beta/rc/testing builds, and future untested minor branches (7.26+) — If MikroTik introduces a breaking syntax change in a point patch on 7.25.x or 7.24.x, an explicit version blocklist will need to be added.`
- `Ruling: Mount static DHCP lease conversion at POST /v1/routeros/leases/static instead of POST /v1/routeros/leases, and emit static with omitempty on GET /v1/routeros/leases — Keeps GET /v1/routeros/leases strictly read-only (preserving TestLeaseDiscoveryIsReadOnly) and backward-compatible for existing clients while allowing explicit, scoped conversion of one bound LAN lease with same-generation readback verification — Minor extra URL segment compared to a verb-overloaded /leases endpoint.`
- `Ruling: Expose events boot_id via X-Tikray-Boot-ID response header on GET /v1/events AND Status.boot_id (omitempty) rather than changing GET /v1/events's JSON array body to an object — Keeps every existing CLI and API consumer decoding []service.Event 100% compatible while enabling the Web UI to detect control-plane restarts and reset seq=0 cleanly — Callers reading events without inspecting headers must read boot_id from GET /v1/status instead.`
- `Ruling: Preserve the installation's existing Network (bridge subnet and RequireLocalBridge) when restoring an encrypted backup on a managed RouterOS installation or local-bridge host — A backup exported on Router A (or standalone) must be restorable onto Router B without mismatching routeros.json's pinned bridge subnet and bricking the container handoff — Operators who genuinely want to change a managed router's bridge subnet still do so via installer re-provision or PUT /v1/network repair.`
- `Ruling: Forbid named API tokens (byToken) from POST /v1/backup/export, POST /v1/backup/restore, and POST /v1/inbox/* (allowing only signed-in admin sessions and root bearer) — Backup export can extract encrypted server credentials using a caller-chosen passphrase, and inbox upload writes release artifacts on disk; restricting both to interactive admin sessions and container-local root prevents privilege escalation from monitoring/automation tokens — Automation scripts that need scheduled backups must use the container-local root CLI (tikray backup export).`
- `Ruling: Keep api.NewHandler JSON-only and add api.NewHandlerWithUI for serving the embedded Svelte 5 UI on non-/v1/* GET/HEAD routes — Preserves strict default-src 'none' CSP and zero-UI guarantees on all API tests while canonical path.Clean routing prevents /v1/../ or //v1/ bypasses from ever reaching the UI handler — Any future standalone API listener must call NewHandlerWithUI explicitly if it wants the browser UI.`
- `Ruling: Commit the compiled Vite output in internal/ui/dist (~49 KB gzipped) alongside web/ sources and enforce dist freshness in CI — Pure-Go builds (go build ./cmd/tikray, make test, scripts/build-images.sh) on minimal Linux hosts and WSL2 environments without Node.js compile seamlessly via //go:embed all:dist — Contributors modifying web/ must run make ui before committing (caught automatically by CI's ui job).`
- `Ruling: Allow style-src 'self' 'unsafe-inline' in the Web UI's CSP while keeping script-src 'self' strictly locked down — Dynamic inline styles (such as latency bar widths and utility spacing in Svelte components) require inline style permission while script-src 'self' and zero @html preserve complete XSS protection — Slightly less strict than hash-only style-src, though zero untrusted user CSS can be injected.`
