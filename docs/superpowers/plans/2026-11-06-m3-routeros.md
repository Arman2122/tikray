# M3: RouterOS integration implementation plan

**Goal.** An owner can install tikray on a supported router, select which LAN clients use it, survive a loss of either container, and remove it again. A second import or reconcile converges without duplicating objects or resetting connections. The tests must demonstrate this from a LAN client while another client and an existing management session continue to work.

**Architecture.** The installer owns the private bridge, container mounts, bridge access controls, restricted account and scheduler. It hands the running service a pinned API-SSL connection and bootstraps a verified xray core with the default direct state. The reconciler in `internal/routeros` owns the traffic rules. A pure planner projects a private, validated snapshot from `store`, the active runner selection and router observations. A single writer applies the smallest safe changes through the native API. RouterOS routes, netwatch and the watchdog work while `tikray serve` is unavailable. The watchdog can restore either container from a previously verified archive on local disk.

**Tech stack and references.** Go 1.24, Go standard library first, RouterOS v7 scripts and native API over TLS, the existing runner trial, `test/lab` and `test/e2e`. The binding [design spec](../specs/2026-10-24-tikray-design.md) covers topology and mounts (§3.2–3.6), verification, geo and image rollback (§4.2–4.8, §4.10), device policies, steering, DNS and failures (§5), install through uninstall (§6), secrets (§7), fake and CHR tests (§8.1, §8.4), and the QUIC carry (§10). Start from the [handoff](../../handoff/README.md), [decisions](../../handoff/decisions/) and [M2c ledger](../../handoff/m2c/ledger.md). The [M0 findings](../findings/2026-10-24-m0-data-path.md) explain the router-local return, conntrack, DNS fallback and TCG constraints. The old spike and `test/e2e/routeros/m1-setup.rsc` are references, never installation inputs for M3.

## Global Constraints

The following requirements come from the spec, with the approved Task 0 decisions recorded below:

- §2: “Never break or reorder the user's own RouterOS configuration.”
- §3.5: “`tikray` gets `/data` read-write. `tikray-runner` gets `/data/cores` and `/data/geo` read-only and `/data/run` read-write.”
- §3.6: “The bridge is created with `protocol-mode=none`.” Give both containers explicit DNS. Masquerade the container subnet only towards WAN. LAN gets the control plane's HTTPS port. The router and control plane can reach the runner's service ports. WAN cannot reach the bridge.
- §5.2: “Packets addressed to the router are never marked” and “Routing follows the connection mark alone”. Preserve the source IP into the runner. The only FastTrack exception accepts tikray-marked connections immediately before the owner's FastTrack rule.
- §5.4–5.6: direct devices keep their DNS. Open devices use WAN and router DNS when the gateway is down. Closed devices use the blackhole and keep their DNS pointed at the runner. Smart domestic and local bypasses stay available. IPv6 forwarding from proxied clients is rejected so applications can fall back to IPv4. All servers down with a live runner is a separate xray balancer case, including the documented encrypted DoH fallback.
- §6.1–6.2: “The installer only bootstraps. It creates no traffic rules; those belong to the reconciler.” Actual objects are selected “where their comment starts with `tikray:`.” “Tables and routes are created before the marks that use them, and removed after those marks.” Settings, startup, owned-object events and a periodic read trigger reconciliation. Keep one API connection and back off after a refused login.
- §6.3–6.5: one independent RouterOS watchdog tick per minute. State migrations write a new version, preserving the previous file. Uninstall asks whether to keep data.
- §7 and owner rules: protect RouterOS credentials as well as server credentials, share links, subscription URLs, root/runner/API tokens, passwords/hashes, session IDs, setup codes and CSRF values/keys. Only `tikray setup-code` may provide the code to the owner at a private terminal. No secret in command history, logs, errors, events, API views, test output or evidence. Use 0700 directories and atomically written 0600 private files. Retain `serve.lock`, the existing API authentication and redacted views. Never mount state in the runner.

**Owner decisions after Task 0.** The owner authorized Task 1 with three binding changes. Certificates created by the installer use a separate tagged receipt recording the name, exact SHA-256 fingerprint and original API-SSL settings. A reused pre-existing certificate is pinned and never recorded as owned or deleted. The owner-run uninstaller restores those settings before deleting a verified installer-created certificate. Tagged user/group removal runs locally as owner, with the control account still exactly `read,write,api`. Every periodic or on-change read is filtered on RouterOS. Route repair uses a 30 s interval and reads own tables and tagged routes. During Task 3 the owner approved one exception per snapshot to establish the live WAN path. Query active IPv4 defaults in main only, projecting gateway, immediate gateway/interface and ECMP. Follow a verified change and refuse an ambiguous next hop. Restrict conntrack reads to affected client addresses. Closed traffic must remain protected independently throughout that interval.

**Execution after plan approval.** Use WSL2 Ubuntu for every command. Begin a ledger at `docs/handoff/m3/ledger.md`. Each task below includes its RED and GREEN command. First run the named new tests and observe the missing behavior, then implement. For imported scripts the decisive test is an actual CHR import, not a string search. After **each** task, obtain a fresh review against its brief, fix findings test-first, run `make test` before **each** commit, record commit IDs, RED/GREEN results and review in the ledger, push the current PR branch with `git push -u origin HEAD`, and tell the owner the outcome. ## Review Focus

1. **Management lockout or interference with the owner's firewall.** Keep a LAN SSH connection open and probe a new one. Take a normalized copy of foreign rows, IDs and relative order, including near-match comments, a foreign mark, a FastTrack rule and a prior deny. Verify those rows, another client's long-lived flow and existing API-SSL access throughout install, policy change, outages and uninstall.
2. **One packet escaping a closed policy.** Inspect every prefix of the planned operations, including disconnect-before-ack, reboot, change from open to closed, stale fast-tracked connections, DNS and IPv6. In CHR, use a WAN-side witness as well as client timeouts. An unanswered request alone cannot prove it was never forwarded directly.
3. **Adopting someone else's object.** Names, list membership, a substring in a comment and RouterOS item positions never confer ownership. Re-read IDs and exact tags at mutations. Detect name, chain, mark and list collisions, duplicate tags and foreign references before modifying anything. Fail with an actionable category rather than widening scope.
4. **A failed install, update or uninstall.** Check the state after every operation and after a second import. Preserve prior allowlists/certificates, old image and state slots, the running data plane and unrelated files. Missing trust, unsafe storage or ambiguous topology stops the operation before switching traffic.
5. **Appearing healthy while taking the wrong path.** Check egress identity **and** counters, runner ping, selected route, resolver observed by the fixture and the lifetime of a connection. Test loss of all upstreams, the runner, xray inside a live runner, control plane and early boot separately. A successful HTTP request at the WAN IP can still have gone through xray's direct outbound.
6. **A secret surviving in evidence.** Raw API traps, RouterOS command output, verbose imports, environment listings, router history, serial logs and test failures are disclosure surfaces. Use generated canaries in success and failure paths. Record fixed outcomes, public counts, versions and timings only.

### Task 1: Version detection and a single pinned API-SSL client

**Files.** Create `internal/routeros/adapters/version.go`, `internal/routeros/client.go`, `internal/routeros/wire.go` and matching `_test.go` files. Use the M0 API probe for protocol examples only.

**Interfaces.** `adapters.Select(version, channel, arch, board string) (Profile, error)` parses numeric release components and validates stable/long-term v7, production ARM64 or actual x86_64 CHR. Each profile specifies supported networking, mount/list syntax, memory and restart fields, disk command vocabulary and which menus have observed notifications or accept ownership comments. Certificates use the approved tagged receipt. Route and conntrack notifications remain unproven. Test 7.23.8 and 7.25 explicitly. Gate at real capabilities and tested version families, refuse unknown behavior before writes. Do not format or repartition an owner's disk. The installer must select the same profile before the Go process exists. Keep a common table of examples for both selectors.

`Dial(ctx context.Context, cfg ConnConfig) (*Client, error)` authenticates only after TLS 1.2+ and verification against the public cert/pin provisioned by the installer. `ConnConfig` holds endpoint, user, password and pin and is never formatted. `Command(ctx context.Context, words []string) ([]Row, error)`, `Listen(ctx context.Context, words []string, notify func(Change)) error` and `Close() error` share one socket, one reader and independent sentence tags. `Row` is a property map. Bound word/sentence/reply sizes, in-flight requests, deadlines and cancellation. Handle `!re`, `!empty`, `!done`, `!trap`, `!fatal`, removed rows and reconnection. Never replay an unacknowledged mutation. Map errors to fixed `routeros:` categories. One supervisor retries with jittered exponential backoff (1 s to 5 min) and signals reconnect so the reconciler can re-read its router-filtered scope. Listen accepts a complete sentence including the router-side query; callbacks report disconnect/reconnect explicitly. No command, including a read, is automatically replayed. `CommandAt(ctx, generation, words)` binds a write to the session used for its snapshot and refuses a replacement generation before sending. Detect the installed profile from bounded singleton resource metadata on each authenticated connection before exposing it to writers. A bad pin never causes insecure fallback. The target CHRs decide which capabilities exist. [MikroTik native API](https://help.mikrotik.com/docs/spaces/ROS/pages/47579160/API)

### Task 2: Compile the router policy and validate its inputs

**Files.** Create `internal/routeros/{model,desired,policy}.go` with their tests. Modify `internal/store/validate.go` and `internal/store/model_test.go`. **Interfaces.** `Project(st store.State) (PolicyInput, error)` strips all server/subscription/private fields. `Desired(in PolicyInput, obs Topology, geo []netip.Prefix) ([]Object, error)` is pure. `Object` holds menu, stable `tikray:<role>[:<key>]` comment, canonical managed properties, dependencies and optional order constraint. Identity includes menu and exact tag, plus canonical member prefix for lists. `Topology` contains the installation subnet, verified LAN/WAN scope, connected LANs, main default next hop, DHCP leases/MACs, IPv6 ingress, existing FastTrack and foreign references. Router facts are read-only. Keep version-specific wire details out of the planner.

- Derive router/control/runner as host offsets 1/2/3 of the configured IPv4 subnet (default `172.31.255.0/29`). Validate devices against each other, the container subnet, loopback and multicast, and the proposed bridge against LAN/connected ranges and reserved addresses. Accept valid LAN devices. Require a verified source of LAN scope and WAN next hop, support changed gateways and fail safely on ambiguous multi-WAN. Never synthesize a global default route in `main`.
- Generate `tikray-local` from private, reserved, connected LAN, and container ranges and `tikray-domestic` from canonical domestic CIDRs including applicable literal state additions. Keep geosite/geoip matchers in xray. Generate `tikray-src-<policy>-<open|closed>` for explicit devices and the default on configured LANs only. Explicit direct overrides and narrower explicit policies take precedence. Router, bridge, WAN, guest interfaces outside the selected LAN, DNS replies and router-originated traffic cannot inherit the default.
- Use one prerouting jump into tikray's chain. Its first rule returns for `dst-address-type=local`. Preserve local and smart-domestic exemptions, mark only new eligible unmarked connections, and route subsequent packets by the connection mark alone. Never override a foreign mark. Clamp TCP MSS on tikray-marked connections. Install the two FIB tables, distance-1 ping-checked runner routes, distance-2 main-WAN fallback for open and blackhole for closed. No masquerade into the runner.
- Put **one** exception immediately before the first relevant enabled forward FastTrack rule. Match only packets of the two owned connection classes, preserve the owner's eligibility/preceding denies and relative order. If an adapter needs a common packet mark, derive it only on those flows and check for foreign mark collisions. Never use “any nonempty connection mark”. No FastTrack means no exception. Refuse an unsupported arrangement before enabling steering.
- Redirect proxied LAN TCP **and** UDP 53 to runner port 53, in separate tagged open/closed sets. `tikray:runner-watch` starts immediately after boot and toggles only the exact open rules. Treat the open rules' enabled bit as netwatch-owned, including during repair. Preserve closed redirects during every outage. Test new DNS transactions separately from old NAT bindings.
- Reject IPv6 **forwarding** for proxied /32s by configured or DHCP MAC and for subnet policies by positively identified dedicated ingress. Respect explicit direct exceptions. Refuse to activate a policy when its guard cannot distinguish the clients, including a mixed subnet on a shared interface with insufficient MAC information. On lease/identity change preserve protection, never reject the whole LAN as a guess. Direct IPv6, local router access and neighbor discovery still work.

**Task 2 implementation decisions.** A pure all-direct target can request detachment while WAN information is unavailable. Activating steering requires a verified effective interface list, disjoint connected LANs, and one identified next hop. A known point-to-point interface may supply that next hop directly. Explicit devices fit in one selected LAN. Existing M2 rules keep explicit prefixes disjoint. Router, network and broadcast addresses cannot supply host MAC exceptions. The compiler emits canonical disjoint CIDRs for the remaining clients.

The FastTrack exception requires an adjacent owner slow-path accept with sufficient eligibility. The observer reports intersecting port forwards, unsafe packet-mark writers, terminal mangle rules and other unresolvable owner interactions as conflicts. The independent egress guard covers paths leaving a managed LAN outside the container bridge, including alternate routing tables. Open-policy DNS uses a router redirect after its netwatch-controlled primary. Stable sibling anchors preserve each private chain and the leading DNS group when repairing individual rows. A repair-only authenticated `PUT /v1/network` can correct legacy overlaps atomically. The [ledger](../../handoff/m3/ledger.md) records the inputs, checks and remaining integration work.
